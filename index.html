GMV 預測模型說明書

依 C2C、Mall、B2C 三個 Biz Type 分別預測下個月（M+1）的全月 GMV，再拆成每日預估，並在月中用 MTD 實際業績校正全月數字。本頁說明如何操作、Dashboard 提供哪些資訊、模型怎麼算，以及每個指標的意思。

01操作說明

每月更新一次預測的流程。資料處理規則見本節最後。

1

更新資料集

將最新的每日 GMV 資料（含 Biz Type、Day Type、ttl_gmv 欄位）存成 data.csv，放在專案資料夾。資料中的最後一天會自動當作 MTD 截止日。

2

執行模型

在終端機執行 py analysis.py。程式會重跑因子篩選、walk-forward 驗證與正式預測，輸出兩份 CSV：因子組合摘要表、預測結果表（2025-01 至預測月份，含實際值、預測值與預測區間）。

3

匯入 Google Sheet

將兩份 CSV 貼入 Dashboard 所在 Google Sheet 的對應工作表，欄位名稱不需完全一致，程式會自動對應。

4

開啟 Dashboard 查看

開啟 Dashboard，選擇 Biz Type 與預測月份，即可看到全月預估、MTD 實際、誤差率、校正後全月預估，以及逐月趨勢圖。

02功能介紹

Dashboard 的六項資訊，每一項都提供 Mall、B2C、C2C 與 All biz type 四種檢視。

全月預估

當月全月預估業績

模型對目標月的 GMV 預測值。All biz type 為三個 Biz Type 相加。

每日預估

當月每日預估業績

全月預估 × 每一天的占比。占比依 Day Type（Spike Day、週末等）計算。

MTD 實際

月初至今實際業績

直接從資料集加總當月 1 日到截止日的實際 GMV。

MTD 誤差率

實際與預估的比值

MTD 實際 ÷ 同期間每日預估加總，用來判斷目前跑得比預測快還是慢。

校正後全月

全月預估校正值

MTD 實際 + 剩餘天數預估 × 誤差率。All biz type 的校正值為三者校正值相加。

04模型邏輯

從候選因子到每日預估共六個步驟。

步驟 1　定義候選因子

各 Biz Type 的候選因子依資料穩定度個別決定。

Mall2024 年業績波動仍大，排除「去年同期 GMV」。保留 YoY 成長率，因為它看的是變化率而非絕對水準。
B2C2024 年仍在快速擴張、非穩定資料，排除「去年同期 GMV」與「YoY 年成長率」。

步驟 2　相關係數篩選

以全部月份計算每個候選因子與實際 GMV 的 Pearson 相關係數，排除 |r| < 0.44 的因子。0.44 是樣本數 20 個月時，相關係數大致達統計顯著的門檻。

步驟 3　選定預測因子

月度資料為 2025-01 至 2026-08 共 20 個月。前 17 個月（2025-01～2026-05）為開發集，用來挑選因子組合；後 3 個月（2026-06～08）為 Hold-out，只用來驗證，不參與挑選。

151015171820
開發集訓練月 開發集預測月 Hold-out 訓練月 Hold-out 預測月
  1. 列出篩選後因子的所有組合。
  2. 每種組合在開發集做 walk-forward：用第 1～6 月預測第 7 月、第 1～7 月預測第 8 月……直到用第 1～16 月預測第 17 月，把每次的誤差取平均得到開發集 MAPE。
  3. 開發集 MAPE 最低的組合，即為該 Biz Type 的預測因子。
  4. 選定組合在 Hold-out 做同樣的逐月滾動（第 1～17 月預測第 18 月，至第 1～19 月預測第 20 月），3 次誤差平均得到 Hold-out MAPE。
  5. Hold-out MAPE 作為模型的最終準度，也用來建立預測區間（± 誤差範圍）。
  6. 不論 Hold-out MAPE 是否輸給 Naive baseline（沿用上月 GMV），各 Biz Type 都採用因子模型預測。

步驟 4　正式預測產出

用選定的因子組合，以全部月份擬合一條迴歸公式。預測時代入以目標月為基準計算的因子值，例如預測 2026 年 9 月時：

去年同期 GMV2025-09

步驟 5　全月預估

各 Biz Type 分別產出全月預估，All biz type 為三者相加。

步驟 6　每日預估

先把每一天歸到一種 Day Type，再依過去 3 個完整月份各 Day Type 的業績占比，把全月預估分配到每一天。過去的日子直接讀資料集的 Day Type 欄位；未來的日子依下表規則標記。

月份Spike Day2nd Spike DayMall Spike
1 月11 號—25 號
4 月、6 月18 號月日同號（DD，即 4/4、6/6）25 號
其他月份（含 2 月，依 2026 年標法）月日同號（DD，如 9/9）18 號25 號

其餘日子歸為 Free Shipping Wed、Weekend 或 Weekday。Mall Spike 三個 Biz Type 都適用；日期重疊時，Spike 類優先於週三與週末。

  1. 取目標月之前 3 個完整月份，算出各 Day Type 占當月業績的百分比。
  2. 百分比 ÷ 該月這個 Day Type 的天數，換算成「每一天」的占比。
  3. 3 個月的每天占比取平均（某 Day Type 某月沒出現時，只平均有出現的月份）。
  4. 把目標月每一天標上 Day Type，填入對應的每天占比。
  5. 加總所有天的占比，再把每天的占比 ÷ 加總，讓全月合計為 100%。
  6. 全月預估 × 每天調整後占比 = 每日預估。
標準化範例　假設 Weekday 每天 3%、共 27 天，Spike 每天 8%、共 3 天。加總 = 3% × 27 + 8% × 3 = 105%。標準化後 Weekday 每天 = 3% ÷ 105% = 2.857%，Spike 每天 = 8% ÷ 105% = 7.619%，全月合計回到 100%。

05相關指標說明

模型篩選與 Dashboard 上出現的指標。

相關係數 r

Pearson correlation

衡量因子值（x）與實際 GMV（y）的波動方向是否一致，範圍 −1 到 1。分子看兩者是否同漲同跌，分母做標準化。|r| < 0.44 的因子會被排除。

r = Σ(x − x̄)(y − ȳ) ÷ √[ Σ(x − x̄)² × Σ(y − ȳ)² ]

MAPE

Mean Absolute Percentage Error

平均絕對百分比誤差，數字越小越準。例如 MAPE 10% 代表預測平均偏離實際約一成。

MAPE = 平均( |實際 − 預測| ÷ 實際 ) × 100%

開發集 MAPE

Dev-set MAPE

在前 17 個月做 walk-forward 得到的平均誤差，只用來比較因子組合、挑出最佳組合。

Hold-out MAPE

Hold-out MAPE

選定組合在最後 3 個月（沒參與挑選）的平均誤差，是模型的最終準度，也是預測區間的寬度依據。

預測區間

± error range

以 Hold-out MAPE 當作誤差範圍，表示實際值大致會落在的區間。

預測區間 = 預測值 × (1 ± Hold-out MAPE)

Naive baseline

沿用上月 GMV

最簡單的對照預測：直接把上月 GMV 當作本月預測。用來檢查模型是否比「什麼都不算」更好，僅供參考，不會自動取代模型預測。

MTD 實際

Month-to-date actual

當月 1 日到資料最後一天的實際 GMV 加總。

MTD 誤差率

MTD actual ÷ forecast

大於 1 代表目前跑得比預估快，小於 1 代表比預估慢。會用來校正剩餘天數的預估。

MTD 誤差率 = MTD 實際 ÷ 同期間每日預估加總

校正後全月預估

Corrected full-month

已經發生的天數用實際值，尚未發生的天數用預估值乘上 MTD 誤差率。All biz type 為三個 Biz Type 校正值相加。

校正值 = MTD 實際 + 剩餘天數每日預估加總 × MTD 誤差率

06已知限制

以下情況目前模型不處理，解讀數字時請留意。

  • C2C 2025-10 一次性異常（Lessons 類別）：預測 2026-10 時，去年同期 GMV 會代入偏高的值。
  • B2C 自 2026-06 起業績大幅跳升：Hold-out MAPE 會偏高，9 月預測可能偏低。
  • 相關係數用全部月份計算：篩選時已看過 Hold-out 月份，Hold-out MAPE 可能略為樂觀。
  • 國定假日與連假沒有獨立的 Day Type，每日預估不會反映假期效應。
